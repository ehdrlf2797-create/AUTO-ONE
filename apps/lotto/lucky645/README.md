# LUCKY 645 (AUTO-ONE module)

기존 LUCKY 645 v1.9 화면과 주요 사용 흐름을 보존해 AUTO-ONE 저장소 안에 독립 앱으로 편입한 모듈입니다.

## 보존한 기능

- 대시보드, 최신 회차 표시
- 완전 무작위 / 균형 / 통계 참고 / 혼합 / 직접 설정 번호 생성
- 번호 통계와 고급 분석, 조합 시뮬레이션
- 독립 시뮬레이션 연구실: 1,000~100,000회 균등 무작위 추첨, 번호별 빈도 그래프, 결과 최대 20개 로컬 저장, 저장 결과 기반 조합 생성
- 당첨 확인, 회차별 이력, CSV/PDF 내보내기
- 로컬 번호 보관함, 백업·복원
- Supabase 로그인 및 클라우드 동기화 UI

현재 페이지 HTML, CSS, JavaScript를 분리했습니다.
- `index.html`
- `assets/app.css`
- `assets/app.js`
- `api/lotto.js`

## 데이터 계약

| 요청 | 응답 | 기준 |
|---|---|---|
| `GET /api/lotto?type=latest` | 동행복권 공식 응답 형태 | 공식 조회 성공 때만 200 |
| `GET /api/lotto?type=all` | 정규화 회차 배열 | 1회부터 연속성 검사 통과 |
| `GET /api/lotto?type=round&round=N` | `data.list` 형식 | 검증된 누적 이력에서 조회 |
| `GET /api/lotto?type=status` | 캐시 상태 | 운영 진단용 |

### 데이터 공급원 정책

1. 최신 당첨 결과는 동행복권 공식 API를 우선 조회합니다.
2. 전체 이력은 공개 JSON 사본을 가져오되 회차 연속성, 번호 6개, 보너스 번호를 검증합니다.
3. 전체 이력 사본은 보조 데이터입니다. 공식 확인으로 표시하지 않습니다.
4. 공식 최신 조회 실패 시 최신 결과 API는 임의 번호나 이전 회차를 최신 공식 결과처럼 반환하지 않고 HTTP 503을 반환합니다.
5. 전체 이력은 6시간 메모리 캐시를 사용하며, upstream 장애 시 마지막 검증된 캐시만 제공하고 stale 표시를 붙입니다.
6. 데이터 검증 실패 결과는 캐시에 저장하지 않습니다.

## 현재 알려진 제한

- Supabase 프로젝트 `lucky645-cloud`는 2026-11-18 기준 `ACTIVE_HEALTHY` 상태입니다. `lucky645_sync_records` 테이블에는 RLS와 사용자 소유권 정책이 적용되어 있으며, `anon` 권한은 제거하고 `authenticated`에는 SELECT/INSERT/UPDATE/DELETE만 부여했습니다.
- 데이터베이스 권한과 정책은 점검했지만, 실제 계정의 로그인·토큰 갱신·PC 간 동기화는 계정 소유자의 브라우저 테스트가 필요합니다.
- 현재 앱은 브라우저 JavaScript가 Supabase Auth 토큰을 사용하며 세션은 `localStorage`에 저장됩니다. Supabase 브라우저 클라이언트의 기본 세션 저장 방식이며, refresh token은 한 번만 사용할 수 있어 동시 갱신 보호가 중요합니다.
- Supabase 조직은 Free 요금제입니다. 유출 비밀번호 차단 기능은 Pro 이상에서 제공되므로 현재 경고가 남아 있습니다.
- HttpOnly 쿠키 전환은 단순 저장소 교체가 아닙니다. 현재 SPA 구조를 서버 중계형(BFF/API 중심)으로 바꾸고, 서버가 인증·세션 갱신·데이터 요청을 처리하도록 별도 설계와 구현이 필요합니다. 현재는 publishable key, 사용자별 RLS, 토큰 갱신 충돌 보호를 유지하고 XSS 방어와 실제 다중 기기 세션 테스트를 후속 점검합니다.
- 판매점 전국 지도는 아직 이 모듈에 편입되지 않았습니다. 기존 UI가 제공하지 않는 데이터를 추정해 표시하지 않습니다.
- 사이트 배포본의 Node 런타임 경고 `DEP0169 url.parse()`는 런타임 경고 로그에서 발견했지만, 현재 소스 일부가 배포 API에서 잘려 제공되어 발원 dependency까지 특정하지 못했습니다. 이 경고를 수정 완료로 표시하지 않습니다.

## 독립 시뮬레이션 연구실

- 공정한 6/45 추첨을 가정하고 45개 중 6개를 중복 없이 선택하는 균등 무작위 표본을 반복합니다.
- 각 번호의 실제 관측 횟수와 번호별 이론 기대 횟수(`실험 횟수 × 6 ÷ 45`)를 함께 표시합니다.
- 시뮬레이션 결과는 브라우저 로컬 저장소에 최대 20개까지 보관합니다. 이 결과 이력은 현재 계정 클라우드 동기화 대상이 아니며, 기기별로 별도 보관됩니다.
- 저장한 결과의 상위 6/8/10/12/15/20개 후보 숫자에서 중복 없는 6개 조합을 만들 수 있습니다. 생성한 조합은 기존 번호 보관함에 저장되며, 기존 보관함의 클라우드 동기화 흐름을 따릅니다.
- 관측 빈도는 실험의 무작위 변동입니다. 자주 나온 숫자를 사용해도 실제 추첨의 당첨 확률은 높아지지 않습니다.


## 번호 추천 전체 저장과 확률 표시

- 번호 추천 화면에서 현재 생성된 조합을 `전체 저장` 버튼 한 번으로 보관함에 저장합니다.
- 이미 저장한 조합, 현재 묶음 안의 중복 조합, 유효하지 않은 조합은 다시 저장하지 않습니다.
- 전체 저장은 브라우저 로컬 저장소에 한 번의 쓰기로 반영합니다. 저장 공간 부족 등으로 실패하면 메모리의 보관함도 새 목록으로 바꾸지 않습니다.
- 저장 요약은 고유 조합 수와 번호 사용 범위, 중복 수 및 1등 확률을 계산합니다. 한 회차에서 고유한 `k`개 조합의 1등 확률은 `k / 8,145,060`입니다.
- 당첨 확률을 실질적으로 높이는 방법은 같은 회차의 서로 다른 조합 수를 늘리는 것입니다. 자동/수동/통계/AI/균형 방식 자체가 한 조합의 확률을 높이지 않습니다.
- 동행복권 온라인 구매는 회차당 5,000원 한도입니다. 생성·저장은 구매 권유가 아니며 예산 범위 안에서 사용해야 합니다.


## AI 연구소 (전략 비교 및 몬테카를로)

- `AI 연구소` 메뉴는 전체 연속 회차를 학습 구간과 마지막 20% 독립 검증 구간으로 시간순 분리합니다.
- 10개 전략군과 10개 기간 조합으로 총 100개 전략을 생성합니다. 각 전략은 과거 구간만 보고 다음 회차의 6개 후보를 구성합니다.
- 결정적 시드의 무작위 기준 전략과 동일한 검증 회차를 비교하고 평균 일치 개수, 3개 이상 일치 빈도, 차이 및 z 점수를 기록합니다.
- 100개 전략을 동시에 비교하는 다중 검정 위험을 줄이기 위해 양의 차이와 z ≥ 3.5를 후보 등록 기준으로 사용하는 보수적 탐색 규칙을 적용합니다. 이 기준은 사전등록된 확증적 통계 검정이나 당첨 예측력 보증이 아닙니다.
- 별도의 1,000,000회 몬테카를로 실험은 공정한 6/45 무작위 추첨의 번호 선택 빈도와 고정 기준 조합의 일치 분포를 점검합니다. 실제 당첨 확률을 바꾸지 않습니다.
- 검증 후보 목록은 브라우저 로컬 저장소에 저장됩니다. 연구 보고서는 로그인 상태에서 별도 연구 이력 테이블로 클라우드 동기화되며, 후보 등록은 기존 번호 추천 엔진을 자동 변경하지 않습니다.
- 연구 실행은 전체 연속 회차가 검증되고 최소 150회 이상일 때 활성화됩니다. 원자료가 누락되거나 끊긴 경우 실행을 막습니다.
- 브라우저를 닫거나 새로고침하면 진행 중인 계산은 중단됩니다. 완료된 연구 결과만 저장됩니다.


### 연구 이력 및 무작위 토너먼트 (v2)

- 연구 실행마다 고유 시드와 실행 ID를 기록해 동일한 설정의 재현이 가능합니다.
- 한 개의 무작위 기준 티켓에 의존하지 않고 독립 시드로 생성한 무작위 참가자 200명이 동일한 검증 회차에 참여합니다. 참가자 수는 연구 프로토콜에서 100~500명 범위로 제한됩니다.
- 100개 전략은 동일한 검증 구간에서 무작위 참가자 평균, 무작위 승률 및 5개 시간순 폴드의 성능 일관성으로 비교됩니다. 표본이 짧을 때 폴드 수는 최소 3개로 줄입니다.
- 전략 후보는 무작위 기준보다 평균이 높고 z ≥ 3.5이며, 최소 80%의 검증 폴드에서 기준보다 높은 결과를 보일 때만 등록합니다. 이는 탐색용 후보 규칙이며 미래 예측력 또는 1등 확률을 입증하지 않습니다.
- 완료된 연구는 브라우저 로컬 저장소에 최근 12회 보관하며, 로그인하면 별도 클라우드 테이블에 전체 실행 이력을 보존합니다. 화면은 최신 실행과 선택한 이전 실행의 100개 전략 평균, 무작위 평균, 최고 전략 및 후보 수를 비교합니다.
- **이력 내보내기**는 연구 이력을 JSON 파일로 내려받고, **JSON 복원**은 검증된 파일을 기존 기록과 병합합니다. 로그인한 계정은 연구 실행 완료 또는 수동 동기화 시 클라우드 이력을 병합합니다.
- 기존 v1 단일 연구 결과는 첫 이력 항목으로 읽어와 새 이력 포맷으로 이어서 관리합니다.
- 몬테카를로 시뮬레이션은 계속 1,000,000회이며 공정한 6/45 분포 검증에만 사용합니다.


### 연구 이력 JSON 복원 및 클라우드 동기화

- JSON 내보내기 파일(lucky645-research-history-v1)을 연구소의 **JSON 복원** 버튼으로 가져올 수 있습니다.
- 최대 12MB, 최대 100개 실행 기록을 허용하며, 버전·생성 시각·회차 수·전략 지표·시뮬레이션 횟수를 검사합니다. 파일 안에 유효하지 않은 보고서가 하나라도 있으면 전체 가져오기를 거부합니다.
- 가져오기는 기존 기록과 실행 ID 기준으로 병합하고 최신 12건을 로컬에 보관합니다. 저장 실패 시 기존 로컬 기록을 복구합니다.
- 로그인 상태에서는 별도 lucky645_research_runs 테이블을 통해 계정별 연구 보고서를 동기화합니다. RLS는 auth.uid() = user_id를 강제하며 anon 및 public 권한은 부여하지 않습니다.
- 로컬 이력은 최근 12건을 유지하지만 클라우드 기록은 과거 실행을 보존합니다. 기존 저장 번호/당첨 확인 동기화와 별도 테이블을 사용합니다.
- 클라우드 동기화는 로그인한 사용자의 인증 토큰으로만 실행되며, 서비스 키는 브라우저에 넣지 않습니다.
