# 자동화 안전 및 승인 원칙

AUTO-ONE은 AI의 판단과 실행 권한을 분리합니다.

## 금지하는 실행 방식
- 모델 출력이나 자연어를 임의 셸 명령으로 변환해 검증 없이 실행하지 않습니다.
- API 키, 비밀번호, 쿠키, 세션 토큰을 프롬프트·로그·저장소에 노출하지 않습니다.
- 웹 UI 요청만으로 사용자의 PC에 무제한 파일·프로그램 접근 권한을 부여하지 않습니다.
- 사용자가 취소한 작업을 계속 실행하지 않습니다.
- 대상·범위가 불명확한 삭제, 전송, 결제, 공개, 계정 변경 작업을 자동 승인하지 않습니다.

## 실행 전 검사
각 작업은 최소한 다음 항목을 선언해야 합니다.
- 작업 ID와 멱등성 키
- 작업 목적 및 사용자가 요청한 범위
- 실행 대상과 입력 데이터
- 요구 권한과 데이터 민감도
- 예상 영향 및 되돌리기 가능성
- 시간·호출·리소스 제한
- 승인 정책과 만료 시각

## 승인 등급 초안
| 등급 | 예시 | 기본 정책 |
|---|---|---|
| 낮음 | 읽기 전용 상태 확인 | 범위가 허용된 경우 자동 실행 가능 |
| 보통 | 임시 파일 생성, 초안 작성 | 정책에 따라 실행 전 확인 |
| 높음 | 파일 삭제·외부 전송·설정 변경 | 명시적 사용자 승인 필요 |
| 매우 높음 | 결제·금융 거래·계정 보안 변경 | 추가 확인 및 별도 제한, 자동 실행 금지 |

## 필수 통제
- 최소 권한 및 명시적 허용 목록
- 구조화된 작업 스키마 검증
- 시간 초과, 취소, 재시도 횟수 제한
- 중복 실행 방지와 멱등성
- 감사 로그에서 비밀 값 제거
- 실패 시 안전한 중단과 복구 안내
- 사용자 승인 없이 권한 범위를 확대하지 않음

이 문서는 설계 기준이며 보안 통제가 실제로 구현되었다는 의미는 아닙니다.
