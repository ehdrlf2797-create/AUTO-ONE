# AUTO-ONE 시스템 아키텍처 개요

## 목표
AUTO-ONE은 PC와 웹을 함께 지원하는 통합형 자동화 시스템입니다. AI는 사용자의 목표와 허용된 컨텍스트를 분석해 작업 계획을 작성하지만, 실제 실행은 독립된 정책·권한 검증 계층을 통과해야 합니다.

## 구성 요소

| 구성 요소 | 역할 | 실행 위치 |
|---|---|---|
| Web UI | 작업 설정, 승인, 모니터링 | 브라우저 |
| Desktop UI | PC 연결 상태, 로컬 권한·작업 관리 | 사용자 PC |
| API / Control Plane | 인증, 작업 조정, 정책 조회, 감사 이벤트 | 로컬 또는 서버 |
| AI Planner | 요청을 구조화된 작업 계획으로 변환 | API 측 |
| Policy Engine | 권한, 위험도, 승인 필요 여부 검증 | 신뢰 경계 내부 |
| Execution Workers | 허용된 작업을 격리된 어댑터로 실행 | 서버 또는 PC |
| Local Agent | 승인된 PC 전용 작업 실행 | 사용자 PC |
| Storage | 설정, 실행 이력, 감사 로그 | 선택한 배포 환경 |

## 기본 작업 흐름
1. 사용자가 목표와 작업 범위를 지정합니다.
2. AI Planner가 제한된 컨텍스트를 바탕으로 구조화된 계획을 제안합니다.
3. 서버가 계획의 스키마, 권한, 대상, 위험도, 시간 제한을 검증합니다.
4. 정책에 따라 사용자 승인을 요청합니다.
5. 승인된 작업만 서버 워커 또는 연결된 로컬 에이전트에 전달합니다.
6. 실행 결과와 변경 사항을 감사 로그에 기록합니다.
7. 실패하거나 취소된 작업은 명확한 상태와 복구 안내를 반환합니다.

## PC와 웹의 역할 분리
웹 UI는 브라우저 권한 범위 안에서 동작합니다. 로컬 파일, 설치 프로그램, 데스크톱 앱처럼 PC에 종속된 기능은 사용자 PC에서 실행되는 로컬 에이전트가 처리합니다. 웹 UI가 로컬 파일에 직접 접근하는 것처럼 가장하지 않습니다.

## 단계별 구현
- Phase 0: 저장소 규칙, Python API 시작점, 헬스 체크, CI, 아키텍처 문서
- Phase 1: 웹 UI, API 인증 기초, 설정·기기 등록의 안전한 기반
- Phase 2: 로컬 에이전트 연결과 작업 권한 모델
- Phase 3: AI 계획 생성, 스키마 검증, 정책 엔진, 승인 흐름
- Phase 4: 제한된 자동화 어댑터와 작업 큐
- Phase 5: 이력·관측성·복구·성능·보안 강화

## 기술 선택 메모
초기 백엔드는 Python 3.14와 FastAPI로 시작합니다. 웹 UI와 데스크톱 UI는 TypeScript 프론트엔드를 공유하고, 데스크톱 패키징은 Tauri를 후속 검토 대상으로 둡니다. 데이터베이스, 메시지 큐, AI 공급자는 실제 요구사항과 배포 환경을 확인한 뒤 어댑터 방식으로 선택합니다.
